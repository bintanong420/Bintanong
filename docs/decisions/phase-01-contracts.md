## What is enforced

- Forbidden status promotion: a state other than the initial one must cite evidence inside the record whose kind and recorder match a transition row, and the row's `from` state must itself have been entered by earlier evidence of the same record (earlier in the list and not dated later; recursive). Its limit: evidence is not bound to a field, so this proves the order of the evidence kinds, not who wrote what for which field. Extraction audit, extractor labels, filenames and possession never match a row. `approval_id` exists only with issuing-office authorization evidence carrying the same reference. That authorization (the earliest one carrying the reference) must not be dated before ANY evidence the approved or revoked state relies on: the acquisition evidence, the verification evidence, and the evidence behind the issuer and every scope field, including a reviewer's "not stated" check. Approval additionally needs verified acquisition, verified scope, verified issuer and a non-proposal category, and a revoked record must still meet every one of those guards (fix pass 3: revoked used to skip them) and cite the reference of the approval it revokes. One authorization reference approves one version; references are compared without case, invisible format characters or dash variants, so `AUTH-1`, `auth-1` and `auth-1` plus a zero-width space are one reference.
- Supersession: a relation needs a target and an observed or verified state; `none` can never be observed or verified (a reviewer's recorded absence, `none` with `not_stated`, stays accepted); the target must record a relation; cycles of any length, a second successor, a change of document and a source document superseding a proposal candidate (or the reverse) are refused.
- Time: every evidence time is a real, timezone-aware calendar timestamp inside 2000 to 2100; `effective_to` before `effective_from` is refused when both are ISO dates (partial dates are compared as ranges; the printed date format is still an owner decision, so other formats are not compared). A value shaped like an ISO date (`YYYY`, `YYYY-MM`, `YYYY-MM-DD`) that is not a real calendar day or month (`2025-02-30`, `2023-13`) is refused even when nothing is compared.
- Paths: `filename` and `Chunk.source_label` are plain file names (no directory, drive, scheme, backslash or control character); acquisition locators are logical references or https URLs, never `file:`, `~`, `..`, drive or absolute paths; the chunk adapter applies the file-name rule to the extractor's `source`.
- Institutional and private mixing: the id patterns are derived from the vocabulary prefixes. Every string, and every key, of a record is scanned for id-like tokens of the other namespace after percent escapes are decoded (up to three layers), invisible format characters (zero-width space and joiner, soft hyphen, word joiner, BOM) are removed, then NFKC, dash-variant and case folding, and a small closed map reads Cyrillic and Greek look-alikes of the prefix letters (a c e o p s i d f t v r n x) as Latin, anywhere in the string (padding, width and dash variants, a trailing path or newline do not hide one). Ordinary prose such as `fact-checking` or `edition-specific` is not an id. Known false positives, pinned by a test and left strict: an institutional file name or hyphenated phrase that reads like an id of the other namespace is flagged (`Fact-Sheet-2024.pdf`, `BS-Fact-1` in an institutional record; `doc-to-doc review`, `Conflict-free-zone` in a session value). See owner decision 22. Each model scans itself, so a bundle, a retrieval result, a symbolic result and an answer envelope (text, citations, decision) refuse private ids; only a symbolic input may cite a private fact. A bundle refuses session facts from two sessions. A decision resting on a student statement is accepted only when the student confirmed it, a rejected statement is refused everywhere, and an `eligible` or `ineligible` result needs at least one input and every input needs a session fact.
- Source anchoring: spans carry the exact byte digest; geometry needs origin AND page size, must be non-empty and lie inside the page; the printed page label is never derived from the physical page; `original_page`/`page_offset` keep the page of the original document when the bytes are one part of a split PDF; a span can locate a section. A chunk's `source_text` must equal the joined text of its spans in span order; a chunk whose spans carry no printed text may only assert `source_text = None` (and is then not citable evidence); identical spans are refused; an unanchored chunk can never claim a version, an edition or a verification state.
- Chunk claims: `verified` or `rejected` source verification needs a `register_binding` that names the register's evidence; `check_chunk_binding` compares both states and both evidence references with the register; `bind_chunk` copies them, so the extractor's content-review label is replaced by the register's state; `type_fields` is deep-frozen and refused if any key at any depth is a privileged status word (case, space and hyphen insensitive) or contains one of the stems `approv`, `verif`, `promot`, `reviewed`, `authoriz` once invisible characters, punctuation, case and look-alike letters are removed (`is_approved`, `promotionstatus`, `reviewed_by`, `verified_by`). None of the keys the extractor emits on a chunk contains a stem (checked on the real BSBA-HRM and IT chunks: `course_code`, `derived_fields`, `content_review`, `prerequisite_state` and the rest). Deliberate in-process bypasses (`dict.__setitem__` on a frozen mapping, `object.__setattr__`, `model_construct`, `copy.copy`) are out of scope; `model_copy(update=...)` validates the whole record again. A retrieval result carries the register versions its chunks cite (no missing, no unused one), checks them with `check_register` and every chunk with `check_chunk_binding`, so a bundle cannot hold an inflated or stale chunk.
- Models and counts: a model revision and a tokenizer revision are a full lowercase commit (40 hex) or digest (64 hex); an exact token count names `tokenizer:<id>@<revision>` with a non-empty id and is never 0; an all-zero fingerprint and an all-zero revision (40 or 64 zeros) are refused; an l2 vector must have a norm within 1e-6 of 1.
- Routing and outcomes: exactly one of route and control outcome; routes and controls are the vocabulary lists; there is no `Direct` route; a symbolic goal is a registered predicate identifier (`^[a-z][a-z0-9_]*$`) plus bound inputs; a bound value is DATA (any printable text up to 128 characters, so `HBO`, `P2101`, `GE- Elect: EM` are values; empty text, padding, repeated spaces, control characters including NUL and newlines, and Unicode format, separator and unassigned characters are refused), and rendering must quote it: `runtime.prolog_quote` is the one way a value may become Prolog, a single-quoted atom with backslash and quote escaped, and it refuses control characters. No Prolog is generated or executed anywhere in the package. A decision predicate has the same identifier shape; an error is operational and never converted; `unknown`, `unsupported` and `error` can never be an approval or a denial in an answer envelope; a decision named `eligible` or `ineligible` carries its scope (release and editions) and the rule spans it was derived from.
- Decision provenance (fix pass 3): the scope and rule spans of a decided result are claims about the register, so an `EvidenceBundle` checks them against the register versions it carries (the retrieval's `versions`, plus the new optional `versions` field a Symbolic bundle uses to carry its own): the scope's knowledge release must be the bundle's, every scope edition and every rule span version must be carried, every rule span digest must equal the bytes of its version, and a rule span must come from an edition inside the decision scope. A decided result with no carried register is refused, unless the decision is synthetic (which establishes no claim at all). The carried versions are themselves checked with `check_register` and must agree with the retrieval's. Nothing checks whether the cited versions are approved; that is owner decision 26.
- Queries: every negation (default list in the vocabulary file, contractions in n't count) and every time qualifier in the original text must survive normalization, and normalization may not add one.
- Envelope: an answered Symbolic or Hybrid envelope needs at least one citation; a passed validation names at least one check; a blank routing reason is refused. Unsupported, unknown and error outcomes may cite nothing.
- Determinism: canonical JSON has sorted keys, two-space indent, LF and one trailing newline; serialise, parse and re-serialise give equal text.

## Adapters

- Chunk adapter (`chunk_adapter.adapt_chunk`): preserves `chunk_id`, `content_hash`, the printed `source_text` and the `estimate-v1` token-count method; recomputes id, hash and derived `pages`/`table_indexes`/`cell_ids` and rejects a mismatch (`chunk_id_mismatch`, `content_hash_mismatch`, `derived_field_mismatch:<key>`). A chunk with no printed text (a Docling table serialization) hashes its own text in the printed slot, as the extractor does, and maps with `source_text = None`. Extractor-side limit (raw text not retained): the extractor hashed the raw serialization text and then dropped it, so when its cleaning changed the text (soft hyphen, dash variants, superscripts) the contract cannot recompute the hash and rejects the chunk as `content_hash_mismatch`. That cannot be told from tampering, so the rejection stays loud and keeps its reason; a pinned test shows it. Retaining the raw text in the chunk, or adding a second hash, is owner decision 23. Fields the contract has no slot for are kept in `type_fields`, not dropped. Rejection reasons are stable strings on `ChunkMappingError.reason`, for example `no_source_spans`, `span_missing_page`, `span_missing_text`, `span_text_without_source_text`, `source_text_differs_from_spans`, `unknown_locator_kind`, `unmapped_span_key:<k>`, `privileged_field:<path>`, `duplicate_source_location` (an identical span), `local_path_in_source`.
- Precise gap: the extractor records a bounding box and its origin but no page size. The adapter will not invent one. By default a chunk with a box and no supplied page size is rejected with `bbox_missing_page_size`. The caller may pass `page_sizes` keyed by (digest, page), or opt in to `on_missing_page_size="omit_and_report"`. Closing the gap properly means the extractor recording page size, which is an extractor change outside this task.
- Real output: the extractor's own builders run on the cached Docling JSON of the BSBA-HRM prospectus gave 61 chunks. With the real page sizes read from that Docling JSON (612 by 936) 48 mapped before the second pass and 58 map now; the three that do not are `hierarchical_layout` chunks whose Docling text is asserted as `source_text` while their spans carry no text (reason `span_missing_text`). Before: 9 `duplicate_source_location` (term schedules, the overview and the enrolment policy share header cells) and 4 `span_missing_text`. The table-serialization layout chunk (`source_text = None`) now maps.
- Routing adapter (`routing_adapter.from_legacy_routing`): duck-types `bintu_client.RoutingDecision` without importing it. Legacy `Direct` raises `LegacyRoutingError` with reason `legacy_direct_unresolved_owner_decision` and a message that names the open owner decision. Legacy `Symbolic` and `Hybrid` are accepted only with a typed `predicate_request` from a validated source.

## Ambiguities resolved with the strict option

1. A bounding box with no page size is refused, not given a default (see the gap above).
2. A box that extends past the page edge by any amount is refused (no tolerance).
3. An anchored span without a physical page or printed text is representable (the extractor emits them) but never complete; it is allowed only in a chunk that itself asserts no `source_text`.
4. Only an identical span (same page, locator and text) is a duplicate within a chunk. Two distinct spans that share a table cell are allowed, because the extractor's term schedules, program overview and enrolment policy share header cells. This replaces the first pass's rule that any shared cell was a duplicate, which rejected 9 of 61 real chunks. It is a labelled strict default the owner may overrule.
5. A decision may be `eligible` or `ineligible` only when every input that came from a student statement was confirmed by the student and every input cites a session fact; unconfirmed statements may still support `unknown`.
6. A legacy routing reason longer than 240 characters is refused, not truncated.
7. A retrieval result that holds two editions of one document, the same bytes under two editions or versions, or one edition over different bytes is refused outright; it is not silently merged.
8. A model or tokenizer revision is a full lowercase commit or digest; names such as `main`, `v1`, `stable` and short hashes are not pinned.
9. A synthetic decision may support only an abstention or an error report, never a decision or passage claim.
10. A conflict that is unresolved or referred blocks decisions only in its own capability; an `unknown` outcome in that capability must list it.
11. Registry default is empty: with no authorized rules every request is `unsupported`.
12. Free-text claims are not parsed: the envelope status and the permitted claims are structural, so wording is not policed.
13. (Replaced in fix pass 3.) The first and second passes refused a bound value shaped like a Prolog variable, a bare operator or text outside a narrow charset. The re-check showed that this refused 18 of the 49 distinct real BSBA-HRM course codes (15 by the variable-shape rule: `HBO`, `TQM`, `P2101` to `P2108`, `E2101` to `E2104`, `Practicum`; 3 by the charset: the colon forms `GE- Elect: EM`, `GE- Elect: ES`, `GE-Elect: PES`) and 2 of 53 IT codes (`GE- Elect: EM`, `GE-Elect: MDS`): legitimate data. A bound value is now data, and the safety belongs in the fixed renderer that always quotes (`prolog_quote`). With that, all 49 BSBA-HRM and all 53 IT codes parse as a `BoundInput` and render to one quoted atom (31 of 49 and 51 of 53 parsed before). The real codes were read from the cached Docling JSON with the extractor's own builders in a scratch run; the committed tests carry only synthetic values of the same shapes.
14. Two spans whose text differs only in whitespace are the same span written twice (fix pass 3); spans with different text on one cell stay allowed.
15. An all-zero 40 or 64 hex revision is a placeholder, not a pin; a key containing a status stem is privileged.
16. A revoked record meets every approval guard, so a revocation over pending acquisition, verification or issuer is refused (the re-check's reproducer).

## Owner decisions needed (none decided here)

1. What legacy `Direct` means (greeting, out of scope, or both) and whether the live router prompt should keep a fourth class. The consumer inventory proposed mapping it to a control outcome; the package refuses it everywhere instead, until decided.
2. Where page sizes come from: should the extractor record them next to every box, or is omitting boxes acceptable for retrieval?
3. Whether a small geometry tolerance outside the page is acceptable.
4. Whether unconfirmed student statements may ever support an `eligible` or `ineligible` decision.
5. Who produces the typed predicate request for `Symbolic` and `Hybrid` routes (router prompt change, or a separate component), and who authorizes capability registry entries.
6. How a source conflict's `capability` maps to a route and to retrieved passages (today the mapping is exact name equality against the symbolic capability only).
7. Whether a comparison query may deliberately retrieve two editions of a document (needs an explicit flag and an answer that names both).
8. The intent taxonomy for `NormalizedQuery` (free text today) and the language set (`en`, `tl`, `taglish` today). The negation and time-qualifier word lists in the vocabulary file (`query_markers`) are English and Tagalog defaults chosen here and need owner review.
9. The exact-token-count convention (`tokenizer:<id>@<revision>`, the revision in the same pinned format as a model revision), which tokenizer, and the pinned embedding model revision. No exact count has been run.
10. The knowledge-release id convention (`release-...`) and who mints release ids.
11. Dependency declaration: `pydantic` is declared directly only in the `api` and `embedding` extras of `backend/pyproject.toml`. `uv.lock` shows that the `tools` extra's `docling` reaches `pydantic` through `docling-slim` and `docling-core`, so under `tools` plus `dev` the package imports an undeclared direct dependency that happens to be installed. Impact is low today; whether to declare it, and in which extra, is the owner's decision. `backend/pyproject.toml` and `uv.lock` were not edited. `jsonschema` is used only through an optional import.
12. Earlier open items remain (see `phase-01-source-governance.md`): document categories, who may record as issuing office, verifier independence (not enforced here), reopening of resolved or revoked records, printed date format, session idle lifetime.
13. The claim vocabulary (`decision_eligible`, `decision_ineligible`, `policy_passage`, `abstention`, `unknown_explanation`, `error_report`) and the control vocabulary (`greeting`, `clarify`, `unsupported_scope`, `evidence_unavailable`) are defaults invented here from a proposal line in the consumer inventory, not a decided vocabulary.
14. Chunks of different chunker versions cannot coexist in one retrieval result (kept as a strict default; the plan does not say).
15. An error status cannot carry a passed validation, a passed validation needs at least one check, and an answered Symbolic or Hybrid envelope needs at least one citation. Because a citation names a retrieved chunk, a Symbolic answer needs a bundle with retrieval; whether a decision should instead be citable through its rule spans is open.
16. The l2 tolerance (1e-6), the pinned-revision format (40 or 64 lowercase hex), the plausible-year window for evidence times (2000 to 2100) and the all-zero-fingerprint rule are defaults chosen here.
17. The vocabulary path is resolved at import time from the package location (`base.py`, `VOCAB_PATH = parents[2] / knowledge / manifests / ...`). Importing the package from a wheel or a Docker image that ships `backend/` alone would fail. Noted, not fixed.
18. Where a decision's scope and rule spans live: this pass put `scope` and `rule_spans` on `SymbolicResult` (not on `DecisionOutcome`, which has a JSON schema and a synthetic example set), required for `eligible` and `ineligible`, optional for `unknown`, and forbidden for `unsupported` and `error`.
19. A bound `register_binding` replaces the extractor's content-review label with the register's state when a chunk is bound; whether an extractor label should ever survive binding is open.
20. Layout chunks whose Docling text is asserted as `source_text` while their spans carry no text are rejected (`span_missing_text`); whether the extractor should attach the text to those spans instead is an extractor-side question.
21. The namespace scan finds an id-like token only if it has a second segment or a digit, so a one-word id without a digit (`doc-handbook`) inside free text is not found; structured id fields are still checked by pattern.
22. Id shape and false positives (fix pass 3). The scan flags an institutional file name or hyphenated phrase that reads like an id of the other namespace: `Fact-Sheet-2024.pdf` and `BS-Fact-1` in an institutional record, `doc-to-doc review` and `Conflict-free-zone` in a session value. Two tightenings were weighed and neither was adopted: requiring a digit (or a minimum length) in the body would remove the last two and `Fact-Sheet`-style names without digits, but would stop catching real one-word and word-only ids such as `doc-synth-handbook` pasted into a session value (decision 21 already lists the one-word limit); refusing a token that follows a hyphen would remove `BS-Fact-1` but let `x-fact-synth-0001` through. Strictness was kept; the owner decides the id shape (mandatory digit or length, or a reserved delimiter) before ids are minted, and whether a flagged institutional file name should be renamed or exempted by an explicit field.
23. Raw text retention for table-serialization chunks (fix pass 3). The extractor hashes the raw serialization and drops it, so the contract cannot verify the hash of such a chunk once cleaning changed the text; it is rejected as `content_hash_mismatch`. Retain the raw text in the chunk, or add a second hash over the cleaned text, is an extractor-side change the owner must decide; the contract's hash was not weakened.
24. Scope of the immutability guarantee (fix pass 3). Frozen models and `FrozenDict` stop accidental mutation. A deliberate in-process attacker can still use `dict.__setitem__` on a frozen mapping, `object.__setattr__`, `model_construct` or `copy.copy`; these are documented as out of scope. `model_copy(update=...)` now validates the whole record again.
25. Bound values and the Prolog renderer (fix pass 3). Values are data: any printable text up to 128 characters (the cap and the refused character classes are defaults to review). The contract cannot enforce what the future renderer writes; the requirement is that a renderer builds Prolog from a registered goal and passes every bound value through `prolog_quote` and nothing else, and that its test runs a hostile value (`X`, `a'b`, `a\b`, `:- foo`) through SWI-Prolog when it is available.
26. Decision provenance and approval (fix pass 3). A decided result must now rest on a carried register (a Symbolic bundle carries its own `versions`), with every rule span inside the decision scope. Whether the cited versions must also be approved (today nothing checks `approval_state` of a version a decision rests on) and whether a decision may rest on a proposal-candidate version are open and belong with Task 4 and the rules owner. The new optional `versions` field on `EvidenceBundle` is a contract addition the owner may rename.
27. Revocation and reopening (fix pass 3). A revoked record must still show the verified states that approval needed, and the authorization date that counts is the earliest one carrying the reference. A record whose acquisition later turned `mismatch`, or whose re-issued authorization is dated after the scope evidence, is therefore refused rather than accepted as revoked; how a register records a later change to an approved version (reopening) is the earlier open item 12.
28. Query words (fix pass 3). The negation list gains `nothing` and `nobody` (`none` was already there); `nowhere` is not in the list. The abbreviation `No.` in `Course No. 101` is read as the negation `no`, so a normalizer that expands it is refused: fail-safe, reported, not special-cased.
29. Authorization references (fix pass 3). They are compared without case, invisible format characters or dash variants for the one-authorization-one-version rule; the pattern still allows such characters in a reference. Whether to forbid them in a reference outright is the owner's call. The look-alike letter map used by the namespace scan is a small closed default (Cyrillic and Greek letters for a c e o p s i d f t v r n x), not a full confusables table.

## Verification

- Counts and the mutation results of both passes are recorded in `plans/phase-01-checkpoint.md`; the numbers below are for this pass.

Second run: 835 mutants, 834 killed, 1 survived (a zero estimate token count at the adapter boundary); a test was added and a targeted re-run of that mutant and its two neighbours killed all three. The harness is not committed; it runs from a scratch directory outside the repository.

- Fix pass 3 (scratch copies only, one mutant at a time, run against the contracts tests, the parity corpus and the test-local checker): 89 targeted mutants of the code and the checker this pass changed (bound-value character classes and cap, quoting escapes, every approval guard on a revoked record, authorization-date coverage, impossible dates, authorization-reference folding, decision provenance, the namespace scan and look-alike map, privileged stems, model_copy, zero revisions, span identity, month ends, the partial end date, id body, time-phrase boundaries, mapping keys, the year window, the vocabulary additions and six rules of the test-local checker). First run: 89 mutants, 82 killed, 7 survived (a private-use character class, taking the latest instead of the earliest authorization, not dating the verification evidence, counting an authorization with another reference, a conflicting duplicate version in a bundle, punctuation inside a stem key, a redundant `min_length`); tests were added for six, and the final run killed 88 of 89. The one survivor is an equivalent mutant (`min_length=1` on a bound value is also covered by the printable-text check, which refuses empty text). The re-check's six survivors (month end, partial end date, empty id body, span text, time-phrase boundary, mapping keys) each have a test that fails against the mutant. The earlier fix-pass-2 figures above are unchanged.
- Real data checks of this pass (scratch only, nothing institutional committed): the 49 distinct BSBA-HRM and 53 distinct IT course codes from the extractor's own output on the cached Docling JSON all parse as a `BoundInput` and render to one quoted atom (31 and 51 parsed before); the chunk keys the extractor emits on those two documents contain no privileged stem.
