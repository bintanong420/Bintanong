# Phase 1 Task 4: pending-source traceability

Task 4 supplies an executable document -> chunk -> synthetic rule draft -> synthetic development case integrity check. It verifies links, not institutional authority or the truth of the invented rule. Task 6 independent review and the Phase 1 exit gate remain outstanding.

`evaluation/traceability.py` reuses SourceDocumentVersion, Chunk, SymbolicResult, CapabilityRegistry, check_chunk_binding, the case checker, canonical JSON and case digests. It accepts exactly one pending source version, one chunk, one rule id/bundle and one synthetic case. Source spans match the rule draft and binding exactly, including text, physical page, locator, geometry, digest and version. Binding pins the chunk id/content hash, the complete rule draft's SHA-256 and the case id/SHA-256. Canonical JSON comparison distinguishes integer pages from booleans or floats. Unknown fields, stale bindings, private-session references, unauthorized state promotion, ambiguous/partial spans, scope assertions and determinate outcomes fail closed.

The checker has a local synthetic capability only; the runtime capability registry, routing and source activation are unchanged. The rule coverage is absent and the outcome unknown. `synthetic_exercise_only` means the printed passage is provenance evidence, never support for the fictional COURSE-A/B prerequisite. The synthetic case retains empty gold spans/rules, null institutional scope and no review evidence. A coherent rewrite with recomputed digests is a new record; this structural checker does not authenticate its writer or independently verify its evidence.
