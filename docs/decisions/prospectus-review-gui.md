# Local prospectus review GUI

Prepared 7 October 2026 on `feat/review-gui-fixes-20261007`, based on GUI integration `cf8b11c` with reviewed publication foundation `3227ac8` merged locally at `1068ef4`. This is the Task 13 decision-record preparation. Task 12's human trial and Task 13's final verification, review and handoff remain pending; this document does not close either task.

The researcher tool uses FastAPI with a local static HTML/CSS/JavaScript page. It reuses the extractor's verifier, geometry, markup twin and ledger rather than adding a Next.js build or desktop renderer. The `review` extra pins FastAPI 0.141.1, uvicorn 0.53.0 and httpx 0.28.1, matching the API extra without its unrelated database/embedding dependencies. Rendering uses the existing pypdfium2/Pillow dependencies. Assets are served locally.

The queue asks course, unclaimed-item, section-confirmation and prerequisite questions. Course Yes accepts the row; No without an edit records an unresolved row; Other records validated corrections with a reason. Course and bulk answers call the sheet's shared `row_entries` builder; `test_review_gui_sheet_equivalence.py` and the Task 11 equivalence checks compare their ledger entries and corrected candidates. Prerequisite answers use `make_entry` directly because the sheet has no prerequisite-answer path: Yes accepts the printed value, Other corrects it (including empty text), and No records unresolved. Every append uses the same append-only, hash-bound ledger and its lock.

Materialisation classifies every corrected course with the original structural ambiguity evidence, then stamps `reviewed_empty` only for a current accepted originally blank prerequisite with one matching course locator. The authority summary is rebuilt from those final states. Materialised candidates always retain `eligibility_executable: false` and the `derived_sections_stale` blocker. Source verification is preserved separately; reviewed content is not institutional approval. Raw candidates and PDFs are immutable, and corrected candidates and ledgers are written outside Git.

The server binds to loopback only. Host checks resist DNS rebinding; POST requires the launch token and a matching Origin when present; the page has a strict CSP and no external assets. This is a local researcher tool, separate from hosted student OCR review. It provides neither missing-course creation nor source/curriculum approval.

The technical review fixes show valid PDF pages for section confirmations without invented boxes, use section-specific image text, and focus the prerequisite cell in the twin for prerequisite questions. Transport or malformed-response failures preserve answers and visibly report POST save status as unknown, since the server may already have committed. They do not retry automatically. GET failures use the existing status live region; answer failures use the alert region. A confirmed save followed by a failed queue refresh leaves that refresh error visible.
