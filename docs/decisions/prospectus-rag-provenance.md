## Source and identity

The canonical `ProspectusEvidence` document is authoritative. Course locators must resolve to its actual cells, with matching table/row/column coordinates and printed text. `verify.own_role_cells` supplies the existing field-role inference. Code, title, units and prerequisite text require complete canonical own-field equivalence; only whole-code spelling equality under existing loose normalization is also supported. Every selected role cell must contain the actual `_source` row, including genuine spanning cells. Unrelated rows, banner/title words, code suffixes and partial prerequisite or unit values do not suffice. Numeric unit values are checked against `parse_units` of the canonical printed unit field. Missing/malformed locators or unsupported fields reject a course explicitly. A blank claim cannot erase a printed own-field value (it is rejected); a genuinely blank or missing own prerequisite cell stays `blank_unreviewed`. Rejected courses never contribute to aggregate text, totals or source spans.

`chunking.py` remains pure stdlib. Source assertion checks live in `rag.py` because they reuse the existing evidence, field-role and unit owners rather than duplicating them in a pure primitive. This is a deliberate deviation from the historical `course_rejection` word-set helper, which could accept wrong-field evidence.

The semantic builder receives the canonical document, the parsed layout, the section evidence IDs and the PDF hash captured for the run (`run_identity.pdf_sha256`, hashed once by `identity.InputSnapshot`). `build_payload` never computes the hash: it accepts `pdf_sha256` as a lowercase SHA-256 digest or `None`, refuses a malformed value, and refuses one that contradicts a declared `ProvisionalSource`. A Docling JSON run has no captured PDF, so its chunks are unanchored (`pdf_sha256: null`, `source_anchored: false`) and a loader must refuse them as institutional chunks. Docling's integer `binary_hash` is never read as a SHA-256. Explicit builder identity arguments support edition-stability tests, not source approval.

Every rejection is recorded in `rag.rejected_chunks` with `chunk_type`, `label`, `reason`, `course_code`, `year_level`, `semester`, `source_cell_ids` (the cells the course claimed; empty when the claim is malformed), `source_item_ids` and `source_refs` (Docling refs such as `#/tables/0`, kept apart from text-item IDs), and, for the review cap, `token_count`. The reasons are named constants in `rag.py`: `no_valid_source_cells`, `code_not_in_source_text`, `title_not_in_source_text`, `prerequisite_not_in_source_text`, `units_not_in_source_text`, `units_not_derivable_from_source`, `over_token_cap`, `duplicate_chunk_id`, `no_accepted_courses`, `no_source_text_items`, `option_not_in_source_text`, `no_source_spans` and `layout_chunker_failed` (the Docling chunker raised; only the exception class name is recorded and the text fallback is used). Rejected courses, and the terms, overview and elective pools that lose all their courses, are reported rather than dropped; a duplicate chunk ID is a rejection, not a silent merge, for layout chunks as for semantic ones. The builders require the `rejected` list, so a caller cannot discard it. `quality_report.total_rejected_chunks` counts them. A blocked audit emits no chunks and no rejections. The record names the course by code and term because the extractor has no separate question or course identifier yet.

Chunk IDs include source edition identity (or `unanchored`), locator, canonical source/summary content hash and chunker version. NFC, whitespace and line endings are canonicalized; source filenames, timestamps and dictionary order do not establish identity. Printed `source_text` stays separate from the advising summary. Extraction method and repair IDs remain on every contributing span. Content review remains pending.

## Geometry and summaries

Pages and coordinate origins come from canonical cells, not the legacy provenance union or filename. The legacy cell projection omits origin, so the builder resolves it from `NormalizedCell.bbox`. Text items already expose their actual origin under `origin`; the span builder preserves that key. Multi-page and incompatible-origin groups remain separate. `BOTTOMLEFT` boxes use their native top/bottom orientation. Boxes with unrecorded origins remain separate because their union direction cannot be inferred; unknown page and geometry stay unknown.

Term, overview, elective and standing summaries retain every contributing span, including option text items and accepted slot cells. Options carry `source_item_id`; tuple-format legacy inputs retain null rather than inventing an ID. Each option must resolve and reproduce the existing elective parser's code/title before inclusion. Rejected options/slots have explicit omission metadata and rejection reasons. Long summaries split while repeating their header; each final rendered estimate is checked. No accepted courses means no course aggregate.

`prerequisite_phrase` is unchanged, preserving blank-unreviewed versus stated-none/reviewed-empty and unresolved/standing wording. Derived unit totals, parsed prerequisite states, classifications and term placement are labelled as derived; program/college/school-year context is unsourced in these chunks. The old negative unlock-completeness statement is omitted because partial extraction cannot prove it. Unlocated BOR/printed term-total statements are also omitted from summary text rather than presented as source-verified PDF assertions. This does not change the extracted course, audit or metadata fields.

## Review estimates and deferred work

`estimate-v1` uses `max(ceil(chars / 3), ceil(words * 1.8))`; 512 and the 32 reserve define a review budget only. They are not an upper bound on the model tokenizer. Exact prefix/special-token-inclusive counting is mandatory before embedding. The 400 target applies to splitting summaries; it does not merge distinct courses.

Layout chunks (Docling's own, or one per text item when there is no Docling document) carry source spans (`docling_ref` or `text_item`), IDs from the edition hash, locator and content, and the same review-cap check. A layout chunk over the cap is rejected, not split: it is Docling's own unit and the curriculum facts are covered by the course and term chunks. A chunk with no source reference is rejected (`no_source_spans`) rather than given an invented location. A Docling chunk's `source_text` is Docling's text unchanged (not cleaned), so it is literal printed text; a table chunk is Docling's serialization of cells, not printed text, so it is marked `text_kind: docling_table_serialization` and carries `source_text: null` (its cells stay behind its refs). Every other layout chunk is `text_kind: printed_text`. A Docling item whose text is blank is skipped without a record (it has nothing to cite); the other items still chunk. A refless Docling item is rejected, never given a null ref. The review cap for layout chunks is the same 480 estimated tokens (512 less the 32 reserve). The payload schema is `palsu-prospectus-v3.3`: a top-level `pdf_sha256`; `rag.chunker_version`, `rag.token_count_method` and `rag.rejected_chunks`; chunks with `chunk_id` in place of `id`; `quality_report.total_rejected_chunks`; elective options with `source_item_id`. `_rag.jsonl` is written with LF line endings and sorted keys, so two runs over the same PDF bytes from different folders are byte-identical and carry no path or timestamp. The JSONL is not byte-identical across renamed copies of the same bytes: `source` and Docling's `metadata.origin.filename` carry the file name (the Phase E plan requires identity across folders only, and is silent on renames). Chunk IDs are rename-stable. Option rows keep `course_code` and `course_title` only for `prolog.py`, which reads nothing else from an option, so the added `source_item_id` does not change Prolog output. The exact tokenizer check (NOT RUN: the model tokenizer is unavailable offline), the GUI trial, source-owner approval and real-photo support remain separate and pending. No embedding, vector write, active curriculum or institutional approval is introduced.
