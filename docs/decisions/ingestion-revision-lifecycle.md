# Ingestion revisions and knowledge releases

Date: 12 October 2026. Status: master-plan interpretation; no implementation or activation authorized by this review.

The owner asked whether ingestion scripts remain revisable before human verification and after Phases 6-9, and whether every revision requires a Supabase migration. The master plan does not permanently freeze ingestion implementation after Phase 2 or Phase 4. Its ingestion boundary is independent of embeddings/database writes (Section 7), and its authorized update workflow explicitly rebuilds reviewed material and publishes a new release (Section 18.3).

- Parser, cleaning, chunking, or review-tool changes that retain the database contract do not inherently require a Supabase schema migration. Regenerate affected candidates from preserved originals and verify source locators, critical fields, and downstream regressions.
- Changed stored text/chunks require compatible new artifact identities and corpus membership. Re-embed affected chunks when content changes; preserve the pinned encoder configuration and query compatibility. A changed encoding configuration requires a separate embedding set. The Phase 04 implementation also binds normal artifact-import set identity to the full corpus, so a changed corpus gets a distinct set identity even with the same encoder configuration.
- Changes to tables, columns, constraints, indexes, RLS, triggers, or database functions require reviewed additive migrations. Published migration history should remain intact. Updating data within an existing contract can use the governed loader/new-release path instead; a specific data backfill may warrant its own versioned migration or job.
- Published evidence and release memberships are immutable under the Phase 04 correction. Corrections must produce a reviewed replacement release rather than mutate published records. Retain the previous release for rollback and provenance; activation remains separately gated.
- Software phase completion is distinct from source/domain approval. Section 7.3 excludes unresolved critical extraction errors from rule authoring; Section 11.1 requires source-to-rule review before approved compilation. Phases 6-9 do not permit these gates to be postponed for live institutional capabilities. Unrelated infrastructure and inactive candidate preparation may continue within their authorized scope.
- The Phase 12 final-evaluation freeze covers the measured configuration/release. Revisions remain possible afterward, but relevant verification/evaluation must be rerun and results attributed to the revised version rather than the previous frozen run.
