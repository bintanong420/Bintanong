## Proposed lifecycle

1. **Readiness before private bytes.** Require a verified, dedicated, size-bounded memory-backed workspace and explicit conversion resource policy. If either is unavailable, private conversion is unavailable; do not fall back to an ordinary temporary directory. Current Windows development may run synthetic containment tests only until its transient storage and process boundary are proved. A future approved Linux deployment may use bounded tmpfs; no Docker/mount/deployment work is part of this draft.
2. **Authorize and reserve.** Reuse the server-issued capability and per-session upload/fact limits. Validate media signatures, byte size and PDF page count. Reserve a global worker/memory slot before admitting bytes; per-session quotas alone cannot bound total in-flight work. Bind the job to the currently live session generation and an opaque job ID. Never accept a user-controlled workspace or parser command.
3. **Own the conversion.** Start only the known worker entry point with anonymous bounded pipes and a noninherited ownership handle. Keep original filenames, grades, tokens and content out of command-line arguments, process names and ordinary logs. The worker owns all parser handles and child processes; the parent owns worker lifetime and the workspace. No arbitrary same-process callback can process real private inputs through this route.
4. **Confine resources.** Set the worker's working directory and writable temporary/cache locations to its owned transient workspace. Preflight all required model files locally; external fetching is disabled and absent models cause a fixed refusal. Independently verify resource/time/output limits rather than trusting a library setting. Read-only institutional models may be reused, but private data may not enter their persistent caches. Production readiness requires proving the installed stack's write destinations, not simply setting TEMP or offline environment variables.
5. **Receive bounded facts.** The parent reads a bounded structured result containing only allowed fact fields, uncertainty and source locators needed for the question. Reparse SessionFact contracts, verify session identity, enforce count/size/type limits, reject duplicate fact IDs and malformed or oversized frames. Parser stdout/stderr are not public diagnostics or persistent logs; no raw page text, image, OCR JSON or traceback is retained as a session artifact.
6. **Clean before commit.** Success means worker and owned descendants have exited, their handles are released, and exact owned transient files are removed. Verify cleanup before facts become visible. A parser result alone is not successful upload completion. Clear parent buffers on every exit where mutable; do not promise forensic zeroization of Python immutable allocations or all operating-system memory.
7. **Delete, expire, cancel or fail.** Invalidate the session/upload generation first so late results cannot commit; cancel only this service's owned worker/job tree, wait within the configured bound, clean its exact workspace, then discard extracted facts and buffers. Never hold the session lock while waiting on worker processes or cleanup. Existing facts/cache clearing and authorization semantics remain intact.
8. **Cleanup fault.** Refuse the upload with fixed ExtractionFailed and no native exception chain, path, token or content. Retain only a private opaque ownership record in transient service memory; block new private admissions and discard in-flight commits while cleanup readiness is unhealthy. Recovery must be autonomous through the worker supervisor/startup lifecycle, not dependent on another user request. If the bounded worker/cleanup policy cannot restore readiness, report conversion unavailable and recycle only the isolated private worker boundary under the separately approved deployment contract. Do not present an unresolved cleanup as erased or retry indefinitely without a recorded bound.
9. **Crash and restart.** Startup refuses private admissions until exclusive ownership of the dedicated transient root is established, old owned workers are absent and leftover owned transient jobs are removed. Discovery is confined to that service-owned private root, never corpus directories or an arbitrary temp tree. Exact targets must pass containment, ownership and no-link/junction replacement checks before deletion. Multiple independent service instances sharing this root are unsupported by the initial design. The process-lifetime mechanism must terminate owned descendants on parent death; ordinary subprocess exit alone is insufficient. Memory-backed storage is not proof against swap, dumps, hibernation or host administrators: those deployment boundaries must be documented and tested before real records.

## Platform and policy boundary

Use a native owned-process lifetime mechanism rather than a generic subprocess plus an optimistic finally block. On Windows, an explicitly owned Job Object can be evaluated for kill-on-owner-close and descendant containment using platform facilities; on Linux, the approved supervisor/cgroup/process namespace must supply equivalent ownership. These are proposed platform choices, not verified behavior, installed services or permission to kill external/owner processes. The original retained-handle reproducer must run in the owned worker and demonstrate that worker teardown releases its handle before cleanup.

Existing draft values—30-minute idle lifetime,8-hour absolute lifetime,10MiB upload size and200 facts—remain owner-reviewable values, not newly approved privacy settings (store.py:24–30). They do not authorize retaining raw files until session expiry. Required worker count, page/pixel cap, memory cap, execution deadline and cleanup/recovery deadline must be explicitly supplied from a measured local conversion envelope and reviewed privacy policy before real-private readiness. Tests can inject small deterministic limits. No unmeasured numeric promise is introduced here.

## Compatibility and minimum change scope

Keep existing session tokens, SessionFact contracts, authorized reads, deletion and answer-cache semantics. Replace or explicitly constrain the extractor admission boundary for private execution; do not silently pickle arbitrary callbacks or execute user-supplied code. The old callback seam may remain synthetic-only during isolated migration, clearly marked as not the approved private runtime. A production entry point cannot route real private files through it as a fallback. Source decisions and the original High remain open until the actual selected path is independently verified.

Expected eventual touch points: bintanong_session/store.py for admission/late-result/commit coordination; one cohesive owned-worker module for conversion and teardown; __init__.py only if an approved public signature requires an export; lifecycle tests/fixtures and draft-session-lifecycle.md for truthful guarantees. No institutional register/chunk/embedding pipeline, rule compiler, runtime router or API transport change belongs to this implementation scope. API cancellation/expiry wiring is a later separately approved consumer task.

## Observable acceptance boundary

Use synthetic private bytes until real-record readiness is reviewed. Required cases: successful extraction and zero retained parser files; retained Windows handle plus parser error; malformed/oversized result; worker exception/timeout; worker or parent interruption; explicit deletion and expiry during conversion; late result refusal; restart with an owned leftover workspace; cleanup target replaced by link/junction; exhausted resource budget; missing local models; cross-session requests; raw-data/path/error/log/repr/serialization leakage; and attempted institutional ingestion of private artifacts. Verify originals/buffers, files, worker descendants, facts/cache and public errors independently. A file absent from directory listings alone does not prove bytes held by another process are gone.
