## Binding approved behavior

approved_execution.md F1 overrides the original plan's cache-first publication order: companions -> main JSON -> staged cache JSON/meta -> manifest. Both converted and reused cache hashes must describe exactly the bytes the loader verified/parsed. Old publish-v1 manifests must fail skip. Pre-publication failures preserve existing published bytes. After interruption either the old coherent set verifies or nothing verifies; after final manifest replace the new coherent set verifies. A passing old manifest is valid when replacements so far are byte-identical and the complete old set remains coherent. Do not require every interruption to invalidate it.

## Smallest concrete interface recommendation

Reuse current internal loader.load_document_result and its DocumentLoadResult fields: document, raw_json_path, cache_status, raw_json_bytes, raw_json_sha256, meta_bytes, meta_sha256. Keep public load_document's two-tuple wrapper unchanged. A PDF internal result must contain both byte snapshots and both digests; absent/partial fields are errors, never infer a cache snapshot by re-reading published paths.

Keep publish_staged's six existing positional arguments and add one keyword-only cache_hashes: Mapping[str, str] | None = None. Its existing cache_files sequence means staged files to replace; cache_hashes means the exact expected complete cache pair. Pipeline supplies:

    cache_hashes = {
        raw_cache_path.name: loaded.raw_json_sha256,
        _cache_meta_path(raw_cache_path).name: loaded.meta_sha256,
    }

Recommended simplest treatment of reused caches: stage the exact captured loaded.raw_json_bytes/meta_bytes too, then pass both filenames in cache_files for every PDF. Converted snapshots are already staged. Validate all staged output/cache names and expected cache hashes before the first publication replace. Hashing staged paths here is a check against loader-provided expected digests, not the source of expected digests. If staged bytes differ, refuse before touching old output. Staging reused bytes avoids blessing a later disk replacement of a cache that was parsed earlier. It has only two small extra writes on non-skipped processing; unchanged batch skips still write nothing. Retain loaded.cache_status for payload cache='converted'/'reused'; stage presence can no longer infer it.

Publish schema: PUBLISH_SCHEMA = 'palsu-prospectus-publish-v2'. Preserve files as output-only digest mapping. Add separate cache_files digest mapping and main_file=names.final.name. PDF cache_files must be exactly one *_docling.json and its matching *_docling.meta.json; JSON review inputs use {}. Add that same cache_files mapping to payload['run_identity'] before serializing main JSON, and publish the identical run_identity into the manifest. This lets verification reject a cache pair swapped for another valid conversion of the same PDF/settings, even if companions are identical. Main-file digest plus embedded exact cache digest mapping binds publication to the parsed snapshot. No new class, dependency, or configurable cache policy is needed.

Keep read_manifest(path) and verify_published(directory, manifest) signatures. Use one private structural validation helper in both so direct verify calls with malformed mappings fail closed as well. read_manifest returns None for old schema, invalid JSON/UTF-8, invalid shape/names/digests; verify returns (False, reason) for structural failure, unreadable/missing files, hash mismatch, or main/meta cross-binding mismatch. Require nonempty files, main_file in files, a valid 64-lowercase-hex run_key, run_identity.run_key equal to top-level run_key, and supported input kind. Reject duplicate/overlapping outputs and cache names at publish input. Require PDF pair when input_kind='pdf', and an empty cache map for 'docling-json'. Read each file's bytes once for verification, hashing and parsing those same bytes for the main/meta checks; do not digest one version and parse a second version. Compare main.run_identity with manifest.run_identity, their cache_files maps, and meta.pdf_sha256/conversion_identity/conversion_settings/raw_json_sha256 with the embedded main run identity and listed raw digest. Catch OSError/ValueError/TypeError as failed verification at this trust boundary.

Leaf-name rules must reject empty names, '.'/'..', slash or backslash, absolute/drive/UNC paths, colon (Windows alternate stream), NUL, and trailing dot/space aliases. Do not depend only on platform Path.name because Windows/Posix separators differ and C:relative and stream names are dangerous on Windows. For existing files require resolved target.parent == resolved directory, so a leaf symlink/junction target cannot escape the output folder. Tests should cover both separators on this Windows host. This is validation of a local file manifest, not an authentication claim; a user who rewrites every artifact and manifest can forge a new set.

Stale cleanup should be only known companions (essentials/prolog/rag/csv/markup) minus current outputs. Delete no arbitrary name from prior manifest files. That single allowlist removes both the reused-cache deletion hole and the ability to delete unrelated neighboring outputs. Cache and main/manifest are never stale companions. Leave stale files that cannot be removed with the existing warning; the new manifest must not list them as current.

## Remaining limitations and phase gates

File-by-file publication remains non-atomic and assumes one writer per output stem; manifest-last detection does not solve concurrent writers, sudden filesystem corruption, or authenticating attacker-rewritten artifacts. Do not add locks/rollback framework unless scope changes. Verification reads must use one bytes value for each digest/parse, and snapshot/mapping values must flow forward from the loader rather than be inferred at publish time.

No F1 implementation/test success is established by this report. Mandatory full suite, selftest80/80, 44-field comparer against base641523d with the real semantic map, stipulated B2/C counts, trial01/16/33 checks, independent spec/quality review, decisionrecord and Task10 handoff remain parent-owned gates. Original plan Task9 conversion failure guarantees byte-identical old files before publication; interrupted replaces only guarantee detectability, so do not overstate byte preservation for mid-publication failure.
